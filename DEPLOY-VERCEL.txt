================================================================================
DropCore — deploy na Vercel (app Next.js na pasta web/)
================================================================================

O repositório tem o Next em web/. Na Vercel isso precisa estar explícito, senão o
build falha ou deploya o projeto errado.

--------------------------------------------------------------------------------
Projeto oficial (obrigatório)
--------------------------------------------------------------------------------

  Nome na Vercel:  dropcore-web
  Time:            dropcore-oficials-projects
  Produção:        https://www.dropcore.com.br
  Root Directory:  web  (no projeto ligado ao Git)

NÃO use o projeto paralelo "web" (criado por engano via CLI sem link). Ele não
tem o domínio oficial nem o mesmo histórico do Git. Variáveis de ambiente vão
só em dropcore-web.

--------------------------------------------------------------------------------
Opção A — Painel Vercel (recomendado)
--------------------------------------------------------------------------------

1. https://vercel.com → projeto dropcore-web (GitHub DropCore-oficial/dropcore-web)

2. Settings → General → Root Directory = web

3. Settings → Environment Variables (Production):
   Copie do seu arquivo local web/.env.local (ou use web/.env.example como lista):
   NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY,
   NEXT_PUBLIC_APP_URL, MERCADOPAGO_*, etc.

4. Deploy: push na branch ligada ao projeto (ex.: main).

5. Depois: no Supabase → Auth → URL Configuration, alinhe Redirect URLs / Site URL
   com https://www.dropcore.com.br (e aliases se precisar).

--------------------------------------------------------------------------------
Opção B — CLI no Mac (só se precisar)
--------------------------------------------------------------------------------

cd /Users/tiagopereirasilva/Downloads/DropCore
npx vercel login
npx vercel link          # escolha o time e o projeto dropcore-web (NÃO "web")
cd web && npm run deploy:vercel    # valida o link e faz deploy na raiz do repo

Não rode npx vercel --prod --yes sem link: isso pode criar outro projeto.

--------------------------------------------------------------------------------
Erros frequentes
--------------------------------------------------------------------------------

- CLI ligado ao projeto "web": rode npx vercel link de novo e escolha dropcore-web.
- "No Next.js version" / build falha no root: Root Directory NÃO está em "web".
- Variáveis faltando: build passa mas login/API falha — reconfigure as env em dropcore-web.
- Repo já ligado com Root = raiz do mono: Settings → General → Root Directory → web

--------------------------------------------------------------------------------
O que já está pronto no Git
--------------------------------------------------------------------------------

Push para main já dispara deploy automático SE o projeto GitHub estiver ligado
ao dropcore-web na Vercel com Root Directory = web.

--------------------------------------------------------------------------------
Go-live Olist / Tiny (pedidos + etiqueta PDF)
--------------------------------------------------------------------------------

1) Supabase (SQL Editor ou CLI), uma vez por projeto:

   a) Rode: web/scripts/add-etiqueta-erp-to-pedidos.sql

   b) Rode: web/scripts/add-seller-olist-ingest-token.sql
      (token `?w=` por seller na URL do webhook — não depende de trocar OLIST_WEBHOOK_SECRET para cada conta)

   Isso cria (se ainda não existirem) as colunas etiqueta_pdf_base64, etiqueta_pdf_url,
   tracking_codigo e metodo_envio em public.pedidos. Sem etiqueta_pdf_base64 o
   import Olist até roda, mas o anexo automático da etiqueta vira só aviso no log.

2) Crons — Supabase (pg_cron), NÃO na Vercel (evita plano/custo extra de Cron Jobs)

   Rode no SQL Editor: web/scripts/supabase-cron-jobs.sql

   a) Habilite extensões: pg_cron, pg_net, Vault (supabase_vault)
   b) Crie o secret no Vault (descomente vault.create_secret no script) com o MESMO
      valor que CRON_SECRET na Vercel (as rotas /api/cron/* validam Bearer)
   c) Jobs agendados (UTC): olist-sync a cada 1 min (* * * * *), mensalidades-mes 9h,
      creditos-expiracao 10h. Re-rode o script se já tinha agendado olist só 1x/dia.

   Vercel → dropcore-web → CRON_SECRET continua obrigatório (Supabase chama a URL
   de produção com esse Bearer). Sem secret, cron responde 401.

   O vercel.json NÃO define crons — só hospedagem do Next.js.

3) Olist — URL do webhook (cadastro no painel Tiny/Olist):

   Preferencial: use a URL que a tela do seller mostra com ?w= (token por conta).
   Legado: ainda funciona ?secret= com OLIST_WEBHOOK_SECRET na Vercel, até migrar.

   https://www.dropcore.com.br/api/webhooks/olist
   (opcional legado: ?secret=… se OLIST_WEBHOOK_SECRET estiver definida)

   Rate limit (opcional): OLIST_WEBHOOK_RL_IP_MAX e OLIST_WEBHOOK_RL_W_MAX — máximo de POSTs
   por minuto por IP e por token ?w= (padrão 200 / 150 se não definir).

4) Depois do deploy: validar um pedido (webhook ou esperar o cron), conferir no
   Supabase se o pedido tem referencia_externa olist:<id> e, quando a Olist já
   tiver expedição, se etiqueta_pdf_base64 foi preenchido.

--------------------------------------------------------------------------------
Mercado Pago / PIX (dinheiro real)
--------------------------------------------------------------------------------

Para cobrança real: token de produção, MERCADOPAGO_TEST_MODE desligado, webhook
na URL de produção. Ver regras do repo e web/lib/mercadopago.ts.
